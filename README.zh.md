# @sumomok/dsh-quote-message

[English](README.md) | 中文

在输入框里精确引用**当前会话**已有的内容：在任意消息里选中一段话，或者用 `@message` 挑一整条消息，一枚原生引用 chip 就把那段文字带进这次提问。

模型于是确切知道"这个"指的是什么，而你没有重新打一遍。

## 为什么需要它

对话一长，代词就变贵。"把你列的第二个问题修掉"要求模型重读上文并猜你指哪一条，猜错的频率高到最省事的补救是手工把原文粘回去。

手工粘贴丢掉了出处：模型看到的是一段没有来历的文字，不知道那是它自己此前的回答，还是你自己此前的提问。这个插件把引用说清楚——角色、位置、原文——并且在你发送之前就以一枚 chip 的形式摆在那里。

## 两个入口

**选中即引用。** 在任意消息里选中文字——用户提问、助手回复、工具结果的文本都算——选区上方浮出一枚 `引用` 小按钮。点击后，chip 追加到草稿末尾，后面跟着输入框自己补的那个分隔空格。之所以落在末尾而不是光标处：输入机器对外发布的草稿状态只有正文和一个修订号，不含光标位置。Escape、点击别处、滚动都会让它消失，它自始至终不会把焦点从输入框抢走。

**`@message`。** 在输入框里打 `@`，候选菜单里多出一组"本会话消息"，按时间倒序列出本会话的消息，形如 `#12 助手 · 消息的前 80 个字符 …`，继续输入按消息正文过滤。选中后插入同一枚 chip，携带整条消息。

两个入口产出同一种 chip：它和内置的 `@file` / `@session` chip 一样渲染，在你继续编辑草稿时保持完整，只在发送时才展开。

## 模型收到什么

发送时，每枚 chip 在它所在的位置展开成一段 markdown 引用块：

```
> [引用 #12 助手消息 msg_01J…]
> 被引用的第一行
>
> 被引用的第二行
```

表头交代出处：`#<seq>` 是会话事件位置，随后是角色，助手消息还带上宿主记录的 message id。跨越多条消息的选区、或落在非消息行里的选区，会退化成 `[引用]` 或 `[引用 #34]`——只报位置、不报角色——而不是干脆不引用。

表头跟随界面语言，且在**发送那一刻**读取而不是插入那一刻：同一枚 chip 在中文界面下序列化成 `[引用 #12 助手消息]`，在英文界面下是 `[quote #12 assistant message]`。下面那行截断提示两种语言下都保持英文：它是对节选长度的度量，不是写给读者的话。

除此之外不注入任何东西。引用块就是你这次提问的一部分，宿主按普通的 `user/message` 记账。

## 边界

- **每条引用 4000 字符。** 更长的消息按码点截断到 4000，块尾补一行 `…(truncated, 9123 chars total)`，让模型知道自己读到的是节选。
- **小按钮是追加到末尾，不是插到光标处。** 宿主发布的输入状态里没有光标可用。
- **只限当前会话。** 跨会话引用是宿主自带的 `@session` 引用的职责。
- **只带文字。** 被引用消息里的图片和附件不会被带上，助手的思维链也不引用——引用带走的是"说了什么"。
- **要改就删掉重引。** chip 插入后不支持原地编辑。

## 安装

```sh
pnpm run build
cd packages/quote-message && pnpm pack --pack-destination ../../dist
dsh plugin --profile <name> add ../../dist/sumomok-dsh-quote-message-0.1.0.tgz
```

发布之后，`dsh plugin --profile <name> add @sumomok/dsh-quote-message` 从 npm 装同一份东西。

清单里声明了 `dsh.bundle.patch`，所以安装会把本包追加进 profile 的 `dsh.profile.bundles`，由它的 patch 层挂载插件；profile 自己的 `cordis.patch.yml` 不需要任何改动。请装 tarball 而不是 `link:` 路径——被 link 的副本会解析到自己的 `@deepseek-ai/*` 并加载第二个 cordis，插件拿到的服务注册表就不是应用真正在跑的那个了。

profile 里需要有组装 Web 界面的 bundle（`@deepseek-ai/dsh-web-app`）；纯 headless 的 profile 里没有东西可看。

## 权限与安全

本插件**纯客户端**。宿主半边是个空实现，存在的唯一理由是让 loader 看到一个真正的 cordis 插件。

- **不联网。** 它不建立任何自己的连接；被引用的文字除了随你发出的提问之外，不离开页面。
- **不碰文件系统。** 无论工作区内外，它不读也不写任何文件。
- **不写自定义会话事件。** 它不往会话日志里写任何东西。它交给模型的一切都走普通提问通道，由宿主记为 `user/message`——所以卸载它绝不会留下一个宿主拒绝加载的会话。
- **不加宿主路由、不加宿主服务、不加 RPC。** Web 服务器和远程 API 上都没有它的新增面。
- **不做持久化。** 引用只活在输入框草稿里，没有缓存、没有 local storage、没有跨刷新的状态。

它确实接触的东西：当前会话的对话快照（只读）、输入触发器注册表（一个 `@` source）、输入区 dock 的一个槽位，以及 `document` 上的选区事件。

## 兼容性

针对 `@deepseek-ai/*` `0.1.1-rc.2` 构建，对应这一代宿主（桌面应用或源码检出）。peer 范围写成 `>=0.1.0-rc.1 <0.2.0` 是为了让预发布版本的宿主能匹配上：按 semver 的预发布规则，`^0.1.0-rc.7` **匹配不上** `0.1.1-rc.2`。

它用的都是公开的缝：`inputTriggers.registerSource`（`ReferenceInsert` 结果 + `ReferenceCodec`）、`conversation.input.dock` 槽位、以及作用域事件 `slash/input-insert-reference`。它不对宿主渲染的气泡做 DOM 手术，不拦截输入框按键，也不装 MutationObserver——它从宿主 DOM 里读的唯一一样东西，是 Web 客户端为自己的滚动锚定打在每个聊天行上的 `data-chat-flow-key` 属性。
