# @sumomok/dsh-edit-rerun

[English](README.md) | 中文

在 DeepSeek Harness 网页界面里挑出更早的一条提问，改一改，从那个位置重新跑一遍——同时保留已有的整段会话。

![编辑更早的一条提问，在 fork 出的子会话里重新运行](https://raw.githubusercontent.com/sumomok/dsh-plugins/main/assets/edit-rerun.gif)

## 为什么需要它

一段会话往往是在某一条提问上走偏的。那条提问下面的回答，以及模型此后做的所有事，都建立在一个漏掉了约束、写错了文件名、或者干脆问错了方向的提示词上。界面此前只给两条路：在最下面重新问一遍，于是错误的那一轮仍留在模型上下文里；或者从头开一个会话，于是本来做对的部分也一并丢掉。

上游[有意移除](https://github.com/deepseek-ai/deepseek-harness)了已发出用户消息上的编辑按钮：当时没有任何能力支撑它；而用户气泡上的分叉按钮是在回答**之后**切分的——与「编辑我的提问」的含义正好相反。上游的记录把「在提问之前切分 + 预填输入框」列为该座位之外的另一件事，这个插件做的就是那件事。

## 它做什么

每一轮已完成对话的操作行（复制、分叉旁边）多出两个按钮：

| 按钮 | 行为 |
| --- | --- |
| **编辑上一条提问并重跑** | 创建一个子会话，其历史正好停在被编辑提问所在这一轮之前，打开它，并把原提问填进输入框，供你修改后发送。 |
| **直接重跑这一轮** | 同上，并立即发送。 |

原会话不会被改动。子会话作为普通会话出现，标题带上 `(1)`、`(2)` 递增编号，会话头部显示上游为每次分叉记录的血缘信息。

## 边界语义

规则只有一条，值得读一遍：

**子会话包含被编辑提问所在这一轮之前的全部内容，且不包含这一轮的任何部分。**

具体地说：对开启第 *N* 轮的那条提问，插件取严格早于它的最后一个已完成轮的 `turn/end`，以该 seq 调用 `sessions.fork({ atSeq })`。上游从「不早于该锚点的第一个 `turn/end`」处切分，然后把切口向后延伸，越过其后的独立事件——自动生成的标题、上下文注入——直到下一个 `turn/start`。于是子会话的种子日志正好停在第 *N* 轮即将开始的位置，种子是一段配平的完整记录，重新提问也不会重复。

同一条规则派生出两点：

- **开启会话第一轮的提问没有更早的边界。** 无处可分叉，插件转而连接该工作区的空白会话——同一目录下的兄弟会话，提问同样预填好。这正是上游「在此新建会话」走的路径；没有历史被丢弃，因为本来就没有。
- **被插话（steering）的一轮，从它的开场提问重跑。** 轮次进行中插入的消息是这一轮对模型可见的历史，而整轮正在被整体替换，因此重跑携带的是开启该轮的提问，不是插话内容。

## 限制

- **只带文本。** 预填只携带提问的文本。含图片或附件的提问根本不显示按钮，而不是悄悄地把图片丢掉、换成另一个问题重问一遍。原提问里的引用 chip 会以它当时序列化出的纯文本形式出现，而不是活的 chip。
- **没有版本树。** 分叉出来的会话在工作区列表里是平级的，和上游自带的分叉按钮完全一样。插件不保存自己的血缘数据，也不提供原会话与各次重跑之间的跳转。
- **首轮那种情况创建的是新会话，不是分叉。** 它用工作区默认标题，而非带编号的子会话标题，也不与原会话关联。
- **分页加载的记录选择拒绝，而不是猜。** 如果你滚动进入一段很长的会话，而当前窗口之上的事件还没加载到浏览器里，最早那一轮不显示按钮：在那里分叉会切错位置。往上滚动，等更早的轮次加载出来即可。
- **按钮针对的是「一轮」，不是「一条消息」。** 它位于轮次的操作行上，所以一轮里有多条用户消息时，重跑的是开启该轮的那一条。

## 权限 / 安全

这个插件只是一个浏览器侧的界面贡献，除此之外什么都不是。

- **不联网。** 不建立任何连接，不请求任何 URL，不访问任何服务。它唯一的 I/O 是客户端自身的会话 RPC，走界面本来就有的那条连接。
- **不碰文件系统。** 不读不写任何文件，工作区内外都是如此。
- **不写自定义会话事件。** 它不向任何会话日志写入内容。你重跑的提问以普通提示词的形式进入子会话，由上游按 `user/message` 记录，和其他提问没有区别。因此卸载本插件不可能让已有会话无法打开——那些自行写入事件类型的社区插件曾把用户的会话彻底弄坏。
- **不注册宿主路由，不含宿主逻辑。** 宿主半边（`lib/index.js`）是一个空的 `apply`，它存在只是因为一个 bundle 需要一个插件入口。
- **只用公开缝。** 两个公开 slot（`conversation.chat.assistant-actions`、`conversation.input.dock`）、三个公开客户端服务（`sessions`、`workspaces`、`locale`）和 slot 注册表。不对上游渲染的消息做 DOM 手术，不拦截键盘，不用 `MutationObserver`。
- **不做任何持久化。** 等待子会话输入框的那条提问存在一个内存 Map 里，上限八条，随页面一起消失。

## 安装

```sh
pnpm --filter @sumomok/dsh-edit-rerun run build
cd packages/edit-rerun && pnpm pack --pack-destination ../../dist
dsh plugin --profile <name> add ../../dist/sumomok-dsh-edit-rerun-0.1.0.tgz
```

发布之后也可以直接：

```sh
dsh plugin --profile <name> add @sumomok/dsh-edit-rerun
```

manifest 声明了 `dsh.bundle.patch`，安装会把这个包追加到 profile 的 `dsh.profile.bundles`，由它的 patch 层挂载插件；同时声明了 `dsh.client`，网页插件表据此把浏览器半边发给前端。profile 自己的 `cordis.patch.yml` 无需改动。

请安装 tarball 或已发布的包，不要用 `link:` 路径——link 安装会加载出第二份 cordis，插件拿到的服务与宿主的就对不上了。

## 兼容性

针对 `0.1.1-rc.2` 的 `@deepseek-ai/*` 客户端包构建；peer 范围接受 `0.1.0-rc.1` 起的任意 `0.1.x` 宿主。注意 caret 范围做不到这一点：按 semver 的预发布规则，`^0.1.0-rc.7` **不**匹配 `0.1.1-rc.2`，这也是这里把范围写全的原因。

插件渲染进 `conversation.chat.assistant-actions` 和 `conversation.input.dock`，两者都是 `@deepseek-ai/dsh-client-ui-conversation` 的公开 slot。如果将来上游改名，插件会在注册时直接报错，而不是渲染到错误的位置。

## 开发

```sh
pnpm --filter @sumomok/dsh-edit-rerun run build   # tsc 声明 + 两个 esbuild 产物
pnpm exec vitest run packages/edit-rerun          # 锚点规则、预填存储、构建冒烟
```

`scripts/build.mjs` 以网页外壳模块加载器要求的闭包工厂格式产出 `lib/client.js`，并把外壳预置的模块（React、cordis、`dsh-client-ui-slots`、`dsh-client-ui-primitives`）保留为 external。构建冒烟测试会用一个替身加载器真正执行产物，因此一个在浏览器里加载不起来的包装会直接让测试失败。
